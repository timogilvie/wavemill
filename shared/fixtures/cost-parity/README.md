# Cost Parity Corpus

This directory contains the **regression corpus** for Wavemill's one cost engine: `@hokusai/costs` measured over a task's owned sessions (`shared/lib/sdk-task-cost/meter.ts`, HOK-3328). It began as the migration oracle that replaced the legacy `workflow-cost.ts` engine (HOK-3074 → HOK-3076); the baseline pins the SDK's output and any drift fails CI.

## Overview

The corpus consists of:

- **`manifest.json`** — Input specification: 16 synthetic test cases covering different scenarios (Claude Code, Codex, native Pi, mixed models, caching, provider costs, etc.)
- **`baseline.json`** — Ground truth output from the SDK metering path (`meterWorkflowCost`), generated by `npx tsx tools/cost-parity.ts --write`
- **`schema.ts`** — Type definitions and validation for the manifest
- **`consumer-inventory.json`** — Machine-readable inventory of every file that imports a cost module — the persisted record shape (`workflow-cost.ts`), the pricing primitive (`pricing/model-pricing.ts`), or session discovery (`wavemill-session-paths.ts`) — classified by type (measurement, pricing policy, report, backfill, etc.). `tools/check-cost-ownership.ts` enforces who may import the primitives (`tools/cost-ownership-allowlist.txt`).

## Privacy

All session files in `manifest.json` are **synthetic** and **privacy-safe**:

- No real transcript text is stored
- Usage metrics are numeric only
- A `"secret-token-should-not-persist"` canary appears in structured fields to catch leaks
- The baseline stripping sanitizes all paths and canaries before storage

## Fixture Format

Cases in `manifest.json` use a compact **logical** shape (camelCase token names,
a per-case `branch` alias, a `session_meta` field on Codex turns, etc.). The
harness's `materializeCase` step translates each line into the **physical**
session-file layout that `ClaudeSessionAdapter`, `CodexSessionAdapter`, and
`NativeSessionAdapter` actually parse (assistant entries with `gitBranch` and
`message.usage.input_tokens` snake_case fields; Codex `session_meta` /
`turn_context` / `event_msg` entries with the real `type` discriminator; native
`session_started` / `assistant_message` events). This translation is the single
boundary between the human-readable fixture and the production parser, so a
regression in translation would collapse the baseline back to `no_sessions`
across the corpus — the `SDK engine reproduces baseline exactly` and mirror-
shape tests in `shared/lib/cost-parity.test.ts` guard against that.

## Running the Harness

### Generate or regenerate the baseline

After an intentional change to the SDK bridge's cost semantics, regenerate the baseline:

```bash
npx tsx tools/cost-parity.ts --write
git diff shared/fixtures/cost-parity/baseline.json  # review changes
```

This is deterministic — running it twice produces identical output. If it doesn't, investigate the nondeterminism before committing.

### Regression test (default)

Compare the current engine against the stored baseline:

```bash
npx tsx tools/cost-parity.ts
# Exit code 0 if all tests pass, 1 if differences found, 2 for corpus errors
```

Cases with an `exact` block run twice: once plain (`sync`) and once with
their stubbed OpenRouter `/generation` responses injected (`exact`), so the
fold of exact charges into SDK events is pinned without network access.

### Inspect a single case

```bash
npx tsx tools/cost-parity.ts --case claude-mixed-one-unpriced
```

### JSON output

```bash
npx tsx tools/cost-parity.ts --json | jq '.'
```

## Legacy Defects (Expected Fixes)

The legacy engine's defects that the SDK engine fixed are documented in
`docs/cost-engine-migration-oracle.md` under "Legacy Behavior and Expected
Fixes". The manifest no longer carries `expectedFixes`: with one engine there
is no "legacy" value left to compare against. Each defect has:

- **ID** (EF-1, EF-2, ..., EF-13)
- **Impact** — which downstream consumers are affected
- **Current behavior** — what the legacy engine does
- **Proposed fix** — what the SDK should do instead

Examples:

- **EF-1**: Partial totals presented as complete (unpriced models add 0 to total, but downstream treats it as the real total)
- **EF-2**: Claude Code usage double-counted (same message id repeated, each line summed)
- **EF-3**: Codex cached and reasoning tokens double-charged

## Integration: HOK-3075 → HOK-3077 (superseded by HOK-3328)

HOK-3075 landed the SDK bridge in `shared/lib/sdk-task-cost/`:

- `collectSdkTaskCostSummaries` scans sessions with the existing adapters,
  emits `TaskCostEventV1` events priced with Wavemill's pricing primitive
  (`shared/lib/pricing/model-pricing.ts`), and reduces each harness with
  `aggregateTaskCost` (`@hokusai/core` 0.5.0).
- `projectTaskCostSummaryToWorkflowCost` maps a summary back to the persisted
  `WorkflowCostResult` / `WorkflowCostAttribution` shape.
- `shared/lib/sdk-task-cost/collect.test.ts` runs every case in this corpus
  through the bridge and requires the projected dollars to equal the baseline
  within 1e-9 (the baseline's dollars are identical to the retired legacy
  engine's on every case).

HOK-3076 made the SDK projection authoritative behind a release gate. HOK-3077
retired the legacy engine, the gate (`cost-migration.ts`,
`compare-task-costs.ts`) and the rollback/shadow switches. Both eval
entrypoints now meter through `shared/lib/sdk-task-cost/meter.ts`:

1. The eval orchestrator fetches OpenRouter exact charges for native turns'
   response ids when `OPENROUTER_API_KEY` is set
   (`shared/lib/pricing/openrouter-exact-pricing.ts`); each fetched charge is
   emitted as that turn's provider-reported `actual_cost_usd`.
2. SDK summaries are collected (lazily — a stale `@hokusai/core` cannot fail
   module load) and persisted as `taskCostSummary`.
3. `resolveWorkflowCost` projects the primary summary into `workflowCost*`.
   The native summary is primary only when the run was native or its
   transcripts carry usable evidence, so an empty native transcript never
   masks the Claude Code / Codex sessions that did the work. No summary is a
   `no_sessions` outcome; a collector failure is an `adapter_error` outcome.
   Neither ever reports `$0`.

Backfills recompute through `shared/lib/sdk-task-cost/recompute.ts`, the
same engine.

Rollback is a revert of the HOK-3077 change, which restores the legacy engine
and its switches while keeping the SDK bridge.

## Re-baseline: `@hokusai/costs` over owned sessions (HOK-3328)

HOK-3074 captured the legacy engine's output as the baseline and HOK-3075–3077
kept the SDK bridge at parity with it — including the native-first harness
selection that discarded every non-native harness's cost. HOK-3328 makes the
engine `@hokusai/costs` itself, measured over the session ids the launcher
recorded in `.session-ownership.jsonl`, so this baseline was **re-baselined,
not kept at parity**. Materialization now writes the launch rows a launcher
would have (a session is owned unless the case marks it `owned: false`), and
`workflowCost` is the SDK report's cross-harness `totalUsd`.

| caseId | old total | new total | why changed |
|---|---|---|---|
| `hok-3237-cross-harness` (new) | $4.93 (incident record) | $48.64 (claude-code $43.71 + native $4.93) | native-first discard fixed |
| `codex-cached-and-reasoning` | $9.9214746 | $1.379284 | SDK codex contract: cached input priced at the cache-read rate, reasoning already inside `output_tokens` (EF-3 double-billing fixed) |
| `claude-branch-filter` | $0 (partial) | $0 (partial) | unchanged total; the other-branch turn is now an unowned session (`owned: false`) instead of a branch filter |
| `missing-sessions` | `no_sessions` | `no_sessions` | unchanged; now means "no launch row names a session" |
| every other case | — | — | single harness, unchanged total (attribution gains `byHarness`) |

The SDK report also adds `byHarness` to every success outcome.

## SDK migration gate (HOK-3076, historical)

Before HOK-3077 the legacy and SDK outcomes were compared on this corpus and
on bounded local historical samples. Every difference had to match a reviewed
rule; the rules still describe how the SDK's output differs from the records
the legacy engine wrote before the cutover:

| Rule | Classification | Difference |
|---|---|---|
| EF-n | `legacy_bug` | A manifest expected fix whose `expected` value the SDK now delivers |
| M-1 | `unpriced_data` | Usage observed, nothing priced: legacy `unavailable` → SDK `partial`; neither reports a dollar figure |
| M-2 | `intentional_contract_change` | Native coverage stays `partial`: the Pi parser coerces missing token fields to 0 and reports no reasoning dimension, so completeness is unprovable |
| M-3 | `legacy_bug` | EF-2: replayed Claude Code lines no longer count as extra turns |
| M-4 | `intentional_contract_change` | Projected native attribution names the harness, not the upstream provider |
| M-5 | `intentional_contract_change` | Priced/unpriced counts are model segments (EF-5) |
| M-6 | `legacy_bug` | EF-13: legacy native `workflowTokenUsage` duplicates/short-counts tokens under raw route ids; SDK equals legacy's own per-model attribution |
| M-7 | `intentional_contract_change` | SDK model-id charset re-keys a model (e.g. Claude Code's zero-usage `<synthetic>`) with an identical value |
| — | `sdk_bug` / `unexplained` | Anything else — **fails the gate** |

The gate also fails, regardless of rules, if a projected coverage is
`complete`/`known_zero` while the SDK total is unresolved, if the projection
promotes a partial/unavailable SDK summary, or if a legacy partial/unavailable
cost becomes complete/known-zero. Any dollar difference above 1e-9 is
unexplained by construction (no rule covers `totalCostUsd` or `costUsd`).

SDK-side (bridge) bugs the gate surfaced as unexplained differences, fixed in HOK-3076:
Claude Code reasoning and Codex cache-write tokens are structural zeros once
a turn reports usage (every fully observed CLI run was mislabelled `partial`);
id-less native turns from several per-model records of one session no longer
collide on one turn id (turn counts were undercounted).

Evidence (2026-10-19): fixtures 15/15 (3 match, 12 approved); 40 local Claude
Code/Codex tasks (15 match, 25 approved); 20 local native tasks (20 approved;
the largest spans 303 sessions and $230.49 with identical dollars). Zero
unexplained differences, zero SDK bugs, zero dollar drift.

### Reporting semantics

- A run that priced nothing has no `workflowCost` (attribution keeps the
  coverage); it never contributes `$0.00` to aggregates. Only an explicit
  known zero records `$0`.
- CLI (Claude Code / Codex) costs are token-equivalent estimates — these
  harnesses run on subscriptions with no per-call charge — and are shown as
  `~$X (estimate)` in eval summaries and `wavemill eval report`. Native cost is
  exact only when every priced model's cost was provider-reported.

## Validation Tests

All harness behavior is tested in `shared/lib/cost-parity.test.ts`:

- Manifest validation (unique ids, known tags, schema integrity)
- SDK engine reproduces baseline exactly
- Comparator detects mutations
- USD tolerance (1e-9)
- Privacy canaries are stripped
- Environment cleanup on error
- Mirror test: harness output matches `collectExecutionEconomics`
- Inventory guard: every importer of a cost module must be classified

Run with:

```bash
node --test shared/lib/cost-parity.test.ts
```
