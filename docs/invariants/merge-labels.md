# Merge labels

`merge-labels.ts` `deriveMergeLabel()` / `reconcileMergeLabels()` - Merge label reconciler invariant (HOK-3181): `wm:ready` / `wm:blocked` are a render of task state. `deriveMergeLabel()` in `shared/lib/merge-labels.ts` is the single source of truth; the per-tick reconciler `reconcileMergeLabelsForPr` applies the difference and corrects the GitHub label, never obeys it. No `wm:ready` / `wm:blocked` write may exist outside `shared/lib/merge-labels.ts` + `shared/lib/pr-state-labels.ts` (`tests/check-label-write-sites.test.sh` enforces this). **One merge-block decision (HOK-3316):** a merge-blocking outcome is a condition-keyed *fact* `deriveMergeLabel` reads, never a label write. Tend records a failed merge attempt (`rebase` / `checks` / `ready` / `merge` / `handoff` / `worktree`) as `.tend-attempt-result.json` (`shared/lib/tend-attempt-fact.ts`, keyed on (PR head, integration base), `--expires-on remote,operator-event`; a moved base is checked by its readers) and the reconciler renders `wm:blocked tend-<phase>-failed` until the head or base moves — one attempt per (head, base). The cross-PR revert guard's `.cross-pr-guard-result.json` verdict is read the same way (`cross-pr-guard`). A rebase conflict is also Ready's merge-conflict signal (`checkMergeConflicts` with the state dir), so the existing one-per-(head, base) conflict resolver launches. Tend's PR comments go through the standing, edited-in-place `postMergeStatusComment` (`shared/lib/merge-status-comment.ts`), one write per `(pr, phase, head, base)` shadow-recorded as a `pr-comment` side effect (`prCommentKey`). **Never write or clear `wm:blocked`, call `setWavemillBlocked` / `releaseToBlocked`, or run `gh pr comment` outside those modules.** Enforced by `tools/check-merge-block-writers.ts` (ratchet `tools/merge-block-writers-allowlist.txt`). **Lane progression labels (`wm:merging`, `wm:merged`, `wm:superseded`) are OUT OF SCOPE for the reconciler** — they are synchronous tend lifecycle transitions (side effects of merge execution), not latched blockers derived from task state. These are managed directly by the merge executor and are not subject to per-tick reconciliation. **One write scope (HOK-3449):** the reconciler's only writer is `setMergeLabel` (`shared/lib/pr-state-labels.ts`), which changes only `wm:ready` / `wm:blocked` (`MERGE_LABEL_WRITE_SCOPE`); it never strips `wavemill`, operator labels (`wm:risk-acknowledged`, `wm:approved`) or lane labels, and a PR holding `wm:merging` gets no reconciler write (stale locks stay tend's reclaim path). Enforced by the `reconciler-label-scope` spec of `tools/check-merge-block-writers.ts` (`tools/reconciler-label-scope-allowlist.txt`).
